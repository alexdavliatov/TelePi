# TelePi compatibility with Pi SDK 1.1.0

## Goal
Upgrade the public fork https://github.com/alexdavliatov/TelePi to @earendil-works/pi-coding-agent 1.1.0 while preserving existing session handoff and Telegram question/answer workflows. Publish verified source changes to GitHub, not npm.

## Human input
Original request: «давай сделаем форк и обновим до версии 1.1.0. Всё запушь в гитхаб, можем паблик сделать».
User chose «SDK 1.1.0 + существующие Telegram-диалоги (рекомендую)», approved the existing SDK bridge approach («Да, этот подход»), and approved automated verification without changing the live bot («Да, подтверждаю»).
The highest-priority use case is answering agent questions from Telegram so execution continues.

## Context
The installed TelePi 0.4.2 depends on @mariozechner/pi-coding-agent 0.70.2, whereas the installed Pi CLI uses @earendil-works/pi-coding-agent 1.1.0. This produced extension-loading errors, model fallback, and a wrong workspace during handoff. Upstream main cc9f30b already migrated to @earendil-works SDK ^0.86.1. This fork starts from that upstream revision, not the old installed distribution.
Relevant code: package.json dependencies; src/pi-session.ts runtime/services lifecycle; src/model-scope.ts model/thinking selection; src/reloading-credential-store.ts credential loading; src/pi-session-paths.ts workspace resolution; extensions/telepi-handoff.ts handoff; src/telegram-ui-context.ts and src/bot/extension-dialogs.ts question adapters; src/bot/prompt-handler.ts extension binding. Existing tests include test/pi-sdk-compatibility.test.ts and session, dialog, and UI suites. Predecessor: none.

## Architecture and scope
1. Keep the existing in-process SDK bridge, directory structure, Telegram transport, and session JSONL persistence. Do not rewrite to RPC or add another orchestration layer.
2. Pin directly consumed Pi SDK packages to exactly 1.1.0 and regenerate the lockfile. No dual compatibility with the old namespace/SDK is required. 1.1.0 denotes the SDK version, not the TelePi release version.
3. Make only compatibility changes required by the new API or verified regression failures. Audit every Pi import and runtime call site, especially runtime/services creation, credential loading, extension binding, session.prompt, and direct agent.state mutations. Ensure the existing bash-timeout and self-management guard survives SDK tool-loadout refresh using supported APIs and a real-SDK test. Use supported context-refresh APIs instead of unsupported message-state mutation when required by 1.1.0. Keep the existing busy/abort contract; no new steering/follow-up behavior. Thinking-level expansion is out of scope unless required for existing saved-session compatibility.
4. Preserve handoff/handback semantics: transfer persisted history, not a running terminal stack, in-flight run, or already-open dialog. Preserve cooperative ordering: launch TelePi before CLI shutdown; dispose its session on handback. There is no cross-process session-file lock: users must not open independent writers simultaneously. No new locking is introduced.
5. Preserve Telegram select/confirm/input through the existing adapter. A valid reply resolves the pending interaction and execution continues; cancellation/abort retain their existing contract.
6. Resume with the session's workspace and workspace-bound settings/extensions. Preserve explicit PI_MODEL override precedence; when unset, restore an available saved model or explicitly report unavailable-model fallback. Do not promise unavailable models/providers can be recreated. Preserve existing headless trust behavior: configured/resumed workspaces are treated as trusted, including their project extensions. Do not add a new trust policy or trust resolver; document this security limitation.
7. Keep custom()/editor() unsupported and document this. Arbitrary Gauntlet/XPowers terminal dashboards and custom question interfaces are outside this change.

## Acceptance criteria
- AC1: The three directly consumed Pi packages are pinned to exactly 1.1.0; the lockfile resolves a consistent SDK graph without duplicate incompatible Pi core/AI copies. Update compatibility-test version literals to the approved version, without weakening tests. Build/import compatibility is verified using the actual target SDK, not only mocks.
- AC2: Existing tests pass without deletion, disabling, weakened assertions, or reduced coverage thresholds. npm run build, npm test, and npm run test:coverage exit successfully on the final diff.
- AC3: At least one real target-SDK integration fixture loads a synthetic extension, binds createTelegramUIContext through session.bindExtensions, and executes its command awaiting select/confirm/input. Resolve each dialog via mocked Telegram callback/reply paths and assert the waiting handler resumes with the chosen value. Retain cancellation coverage including AbortSignal. No production bot token or LLM inference call is required.
- AC4: Isolated real-SDK session tests verify saved workspace, available-model restoration with PI_MODEL unset, explicit override precedence, unavailable-model fallback diagnostics, and loading a synthetic project extension without a new trust prompt. Extension fixtures must import actual exported target-SDK symbols, replacing obsolete imports without weakening assertions. Handoff shutdown/disposal ordering remains covered. No real user session, credential, or provider call is required.
- AC5: README accurately names Pi 1.1.0, fork installation from GitHub/build explicitly checking out feat/pi-1.1.0, history-only handoff semantics, cooperative concurrency limits, headless workspace trust, and unsupported custom/editor interfaces. Installation instructions do not publish or suggest ownership of the upstream npm package.
- AC6: Commit intended source, tests, docs, and this spec; push feat/pi-1.1.0 to the public fork and provide its link and verification output. Default branch remains upstream until separately accepted. Keep npm package name and license/upstream provenance; point package repository/homepage/bugs metadata at the fork. Guard the npm-publishing workflow so it runs only in the upstream repository and cannot publish from this fork. Add an explicit fork note to AGENTS.md release guidance. Do not publish npm packages or create release tags.
- AC7: No credentials, tokens, local configs, Telegram user IDs, logs, real session JSONL, or temporary review artifacts enter Git history. Do not modify global installed packages, model routing, or restart/reconfigure the live bot. Actual Telegram end-to-end testing/deployment requires separate authorization.

## Verification approach
Establish baseline in the isolated worktree, then add targeted regression tests where current coverage does not prove the approved contracts. Real-SDK tests set PI_CODING_AGENT_DIR to a per-test temporary directory before resolving SDK services, restoring environment afterward. Use synthetic auth/model configuration with an offline model, temporary version-compatible session JSONL and project extensions, and disable model-network refresh. Never fall back to ~/.pi/agent. Verify the fixture model is registered/available without external credentials. Exercise target SDK integration with these temporary synthetic workspaces, sessions, and extension fixtures. Run the repository's build, full tests, and coverage on the final diff; inspect outgoing tracked files for accidental sensitive artifacts. Independent code and closure reviews cover the complete change against this spec and original request. Automated transport tests are not a claim of live Telegram or custom-TUI compatibility.

## Documentation impact
- Feature / user-facing docs introduced: none

## Out of scope
npm publication; live installation/service restart; new Telegram UI capabilities; arbitrary terminal custom UI; new trust/security policy; changes to shared Pi extensions; concurrent live CLI/Telegram control of one runtime; support for old SDK versions.
